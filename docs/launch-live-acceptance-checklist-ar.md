# قائمة القبول الحي للإطلاق التجريبي — ترتيل

**الغرض:** التحقق من السلوك الذي لا يمكن أن تثبته اختبارات الخادم وحدها، باستخدام حسابات حقيقية منفصلة وبأقل تعديل ممكن على البيانات.  
**قاعدة الخصوصية:** لا تلتقط رمز دخول كاملاً أو أرقام تواصل أو بيانات طالب حساسة في لقطات الإثبات.

## قبل البدء

أنشئ المدير كود دخول منفصلاً لكل حساب اختبار، ثم يسجل كل مستخدم دخوله ويسترد الكود الخاص بدوره. لا تستخدم محاكاة الدور لهذا الاختبار؛ فهي تفيد في معاينة الواجهة فقط ولا تثبت حراسة الخادم. يفضل البدء بمركز تجريبي واحد، وحلقة واحدة، وطلاب موجودين فعلياً.

| الحساب | النطاق المطلوب | التجهيز |
|---|---|---|
| مدير مركز | مركز التجربة | حساب منفصل عن حساب المالك التقني إن أمكن |
| مشرف | المركز نفسه | كود مشرف مستقل |
| موجّه | حلقة واحدة محددة | كود موجّه مقيد بالحَلَقة |
| معلم | حلقة واحدة محددة | كود معلم أحادي الاستخدام |
| معلم مساعد | الحلقة نفسها | كود مساعد مستقل |
| طالب | طالب واحد | كود طالب مقيد بالطالب |
| ولي أمر | ابن واحد | كود ولي أمر مقيد بالابن |

## حالات القبول

| الدور | حالة نجاح يجب أن تعمل | حالة رفض يجب أن تفشل | النتيجة |
|---|---|---|---|
| المدير | إدارة المركز والحلقات والأكواد والتقارير | محاولة فتح مركز لا يملك عضوية فيه | ☐ نجاح ☐ فشل ☐ ملاحظة |
| المشرف | عرض وإدارة العمليات التعليمية الممنوحة | تعديل إعدادات المركز أو حذف المستخدمين إن لم تمنح له | ☐ نجاح ☐ فشل ☐ ملاحظة |
| الموجّه | قراءة الحلقة المحددة وتقريرها | فتح رابط حلقة أخرى أو تعديل طالب | ☐ نجاح ☐ فشل ☐ ملاحظة |
| المعلم | إضافة أو تعديل طالب في حلقته، وفتح جلسة للحلقة | نقل طالب أو إنشاء جلسة لحلقة أخرى | ☐ نجاح ☐ فشل ☐ ملاحظة |
| المعلم المساعد | تسجيل حضور ضمن الحلقة | إضافة طالب أو إدارة كود دخول | ☐ نجاح ☐ فشل ☐ ملاحظة |
| الطالب | قراءة تقدمه وآخر حفظ ومراجعة | فتح ملف طالب آخر أو قائمة حضور الحلقة | ☐ نجاح ☐ فشل ☐ ملاحظة |
| ولي الأمر | قراءة حضور وإنجازات الابن وتقاريره | فتح بيانات ابن آخر أو أي إجراء تعديل | ☐ نجاح ☐ فشل ☐ ملاحظة |

## اختبار رحلة الجلسة

ينفذ المعلم جلسة تجريبية واحدة على بيانات مسموح بتعديلها. يبدأ بإنشاء مسودة بتاريخ محدد، ويتحقق من ظهور طلاب حلقته فقط، ثم يسجل حضوراً ونطاق حفظ أو مراجعة لطالب واحد، ويغلق الصفحة ويعود إليها للتحقق من استمرار المسودة، ثم يعتمد الجلسة. بعد ذلك يتحقق المدير أو المعلم من أن بياناتها تظهر مرة واحدة فقط في التقرير المناسب. لا تنشئ جلسة بتاريخ مكرر إلا إذا كان الهدف اختبار رسالة التعارض ثم تغيير التاريخ بوضوح.

| الفحص | النتيجة |
|---|---|
| فتحت المسودة في سجل طلاب الحلقة مباشرة | ☐ |
| ظهر طلاب الحلقة فقط | ☐ |
| احتفظت المسودة بتعديل الحضور والإنجاز بعد إعادة الفتح | ☐ |
| منع النظام التاريخ المكرر برسالة مفهومة | ☐ |
| لم يظهر أثر الجلسة في التقرير قبل الاعتماد | ☐ |
| ظهر أثر واحد صحيح في التقرير بعد الاعتماد | ☐ |

## معيار القرار

يمنع الإطلاق التجريبي فوراً أي وصول إلى مورد خارج النطاق، أو ظهور إجراء تعديل لحساب قراءة، أو إدراج جلسة غير معتمدة في التقارير، أو فقدان مسودة أثناء الاختبار. أما الملاحظات غير المانعة مثل تحسين تسمية أو مسافة بصرية، فتسجل وتدخل قائمة الإصلاح قبل التوسع إلى مركز آخر.

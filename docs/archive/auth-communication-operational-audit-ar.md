# تدقيق المصادقة والتواصل التشغيلي — ترتيل

**الحالة:** يوجد دخول فعلي عبر Manus OAuth وأكواد وصول مقيدة بالدور والنطاق. توجد إشعارات داخلية مخزنة للمستخدم، ومنها إشعار المدير عند استرداد كود الدخول. لا يوجد حتى الآن تسجيل مستقل بالبريد وكلمة مرور، ولا تحقق عبر رمز بريد خاص بترتيل، ولا Google OAuth مستقل ضمن التطبيق.

| المجال | الحالة الفعلية | قرار المرحلة |
|---|---|---|
| الدخول الحالي | Manus OAuth مع حماية حالة OAuth وأكواد وصول | الحفاظ عليه وتحسين الإرشاد فقط |
| إنشاء مركز مستقل | متاح للحساب الجديد بعد الدخول | الحفاظ على المسار وإظهار دعم واضح للوصول |
| الإشعارات الداخلية | موجودة، قابلة للقراءة والتعليم والفلترة | إضافة إجراءات سريعة للأنواع ذات الوجهات الثابتة فقط |
| البريد التشغيلي | غير مربوط بتطبيق ترتيل | لا يضاف إرسال أو زر بريد قبل التحقق من المرسل والنطاق |
| Google OAuth مستقل | غير مربوط | يتطلب عميل OAuth مخصصاً وبيانات اعتماد صحيحة واختبار تحويل حقيقي |

## نتيجة فحص خدمة البريد

ظهر اتصال Resend متاحاً للقراءة والتعامل مع الإرسال، لكن فحص نطاقات المرسل أعاد رفض صلاحية لأن المفتاح الحالي **مقيد بالإرسال فقط**. لذلك لا يمكن حالياً التحقق من نطاق مرسل أو سجلات DNS أو جاهزية الإرسال الإنتاجي عبر هذا الاتصال. كما أن استخدام عنوان تجريبي لا يصلح لمسار مصادقة أو إشعارات تشغيلية للمستخدمين.

> لن يضيف ترتيل رسالة تحقق أو «دخول Google» أو زر إرسال رسالة خارجية قبل ربط بيانات اعتماد خادمية، ومرسل متحقق، ومسار استلام واختبار حقيقيين.

## ما ينفذ الآن دون اعتماد خارجي

تواصل هذه المرحلة بتحسين الإشعارات الداخلية المرتبطة فعلياً بأكواد الوصول والفترات، وإضافة مركز دعم للوصول يشرح الطريق الصحيح للحساب الجديد أو صاحب الكود. أما تفعيل البريد أو Google OAuth المستقل فيبقى خطوة ربط لاحقة تحتاج قراراً من المالك وبيانات خدمة حقيقية.

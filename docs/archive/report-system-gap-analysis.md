# مطابقة متطلبات نظام التقارير مع ترتيل

## القرار التصميمي

تحتفظ ترتيل بتصدير PDF وExcel وCSV وWord الحالي، وتستخدم هوية التطبيق العربية RTL وخطوطه والرموز اللونية الدلالية. لا يُعاد نسخ التقرير المرجعي أو تصميم ثيم منفصل؛ بل يُبنى تدفق تقرير موحد فوق مصدر البيانات الحالي ثم تستفيد منه المعاينة والطباعة والتصدير.

| المتطلب | الموجود حالياً | قرار الدفعة |
|---|---|---|
| اختيار الحلقة والفترة وتصديرات أساسية | موجود في صفحة التقارير وأزرار التصدير | يوحّد ضمن نافذة إعداد تقرير بأقسام وخيارات أوضح. |
| PDF وExcel وCSV وWord | موجودة للتقارير الأساسية | يبقى الدعم، ويضاف PDF موحد لتقرير الحلقة/الشامل دون استبدال المولدات القديمة. |
| أرشيف التصدير | سجل محلي لعمليات التصدير | يعاد عرضه كأرشيف منظم داخل تدفق التقرير الجديد. |
| رأس التقرير وملخص وحضور وكتل الطلاب | موزعة بين تقارير منفصلة أو غير متاحة | تبنى من نموذج بيانات موحد ومعاينة RTL. |
| حفظ ومراجعة متعددتان لكل طالب | بيانات قاعدة البيانات موجودة | تُجمع داخل كتل طلاب مستقلة مرتبة زمنياً. |
| التقدير والصفحات | تقديرات نصية وصفحات اختيارية موجودة | تستخدم القيمة الأصلية؛ ويعرض التقدير من النظام القائم، دون اختراع درجات جديدة. |
| معاينة وطباعة ومشاركة | تنزيل فقط مع قوالب رسائل يدوية في قسم آخر | تضاف معاينة قابلة للطباعة ومشاركة متصفح عند دعم الجهاز، مع بديل تنزيل واضح. |
| تخصيص شعار وتحكم دائم بإعدادات التقييم | غير موجود | لن تنشأ إعدادات ثابتة جديدة في هذه الدفعة؛ الخيارات مؤقتة داخل إعداد التقرير وتحترم هوية ترتيل. |
| حذف أو تعديل السجلات من التقرير | غير موجود | خارج نطاق التقرير، لتجنب مزج التحرير التشغيلي بطبقة القراءة والطباعة. |

## نطاق التنفيذ

ستضيف الدفعة طبقة `ReportBuilder` تحول البيانات الفعلية إلى نموذج تقرير شامل للحلقة، وواجهة إعداد بمعايير الحلقة والفترة والطلاب والأقسام والترتيب، ومعاينة RTL صالحة للطباعة. سيستخدم التصدير PDF النموذج نفسه مع ترويسة وملخص وجدول حضور وكتل طلاب وفوتر وترقيم صفحات. تظل صفحات Excel وCSV وWord السابقة خيارات مساندة ومتصلة بسجل التصدير الحالي.

## تحقق واجهة الإعداد

ظهرت صفحة التقارير بهويتها RTL الحالية مع لوحة **إنشاء تقرير جديد**. تحققت قائمة نوع التقرير، اختيار الحلقة، الفترة، الأقسام، ترتيب الطلاب، ثم عرضت عند اختيار حلقة **نسائم الجنة** الطالبتين المرتبطتين بها كاختيارات إضافية. لم تتغير بطاقات الإحصاءات أو سجل عمليات التصدير القائم؛ بل استمر ظهورهما أسفل تدفق الإعداد الجديد.

## تحقق المعاينة الحية

أُنشئت معاينة تقرير شامل لحلقة نسائم الجنة ببيانات فعلية. ظهرت ترويسة ترتيل واسم الحلقة ونوع التقرير والفترة، ثم ملخص الحلقة وجدول الحضور RTL. كما ظهرت لكل طالبة كتلة مستقلة تضم الحضور وسجل الحفظ المرتب زمنياً باسم السورة والآيات والتقدير والتاريخ. ظهرت أزرار الطباعة والمشاركة وتصديرات Excel وPDF وCSV وWord، مع بقاء الإحصاءات وسجل الأرشيف القائمين في الصفحة.

بعد تحديث الواجهة، أعيد اختيار الحلقة بنجاح وعادت خيارات الطلاب ومعايير التقرير من دون أخطاء أو فقدان لتدفق الإعداد. سيستمر التحقق النهائي باختبار زر PDF الموحد من معاينة فعلية.

تم إنشاء **PDF موحد** فعلياً من معاينة تقرير نسائم الجنة. ظهرت رسالة نجاح داخل الواجهة، وسُجِّل التقرير الموحد بتنسيق PDF في أرشيف عمليات التصدير المحلي مباشرة. يعيد هذا المسار استخدام نموذج التقرير نفسه ويغطي الترويسة والملخص وجدول الحضور وكتل الطلاب والفوتر وترقيم الصفحات في ملف A4.

## التحقق النهائي والقيود المعلنة

جرى تضمين خط **Amiri** العربي في مولد PDF من تبعية التطبيق نفسها بدلاً من الاعتماد على Helvetica أو خط نظام غير مضمون في بيئة النشر. يختبر التشغيل الفعلي الآن ترويسة `%PDF`، ووجود الخط المضمّن، وتوليد أكثر من صفحة عند تكثير كتل الطلاب؛ كما يبقى فحص المصدر متحققاً من الفوتر والترقيم. لا يدّعي هذا التحقق مطابقة بصرية يدوية لكل قارئ PDF، لكنه يزيل القيد السابق المتعلق بغياب الخط العربي داخل الملف.

تُشارك الواجهة **ملف PDF الناتج نفسه** عبر Web Share API عندما يدعم المتصفح مشاركة الملفات. وعند عدم دعم ذلك، تنزّل الملف مع رسالة تشرح أن مشاركته تتم من التطبيق المناسب، ولا تدّعي الواجهة إرسال الملف مباشرة عبر جميع التطبيقات. يظل الأرشيف المحلي سجلاً لعمليات التصدير على المتصفح الحالي وليس مخزناً دائماً مشتركاً بين المستخدمين.

كما تحققت فترة خالية فعلية للحلقة نفسها؛ بقيت كتل الطالبات منظمة، وأظهرت الخلاصة والحضور صفراً ورسالة صريحة لغياب عمليات الحفظ والمراجعة. لم تُنشأ بيانات اصطناعية ولم تتغير التصديرات السابقة أو حراسة الخادم لنطاق الحلقة.

خلال الفحص البصري للملف الأول ظهر ترحيل فارغ سببه وضع الفوتر أسفل الهامش الداخلي. عولج الموضع ثم أُعيد توليد الملف من الواجهة؛ أكد فحص الملف الأخير أنه صفحة واحدة فقط مع الفوتر، وتغطي الاختبارات حالتي التقرير القصير ذي الصفحة الواحدة والتقرير الطويل متعدد الصفحات.

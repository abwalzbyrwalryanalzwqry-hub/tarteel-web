# دليل مبسط: تفعيل بريد التحقق لترتيل عبر Supabase وResend

## قبل أن تبدأ

لقد أنشأت مشروع Supabase جديداً باسم **`tarteel-auth`** لمنصة ترتيل، لذلك لا تحتاج إلى إنشاء مشروع Supabase بنفسك. المطلوب منك الآن هو امتلاك نطاق إنترنت تستطيع تعديل سجلاته، مثل `example.com`، ثم إثبات ملكيته في Resend. لا تكتب أي كلمة مرور أو مفتاح API داخل محادثة ترتيل أو GitHub.

> إذا لم يكن لديك نطاق، توقف عند الخطوة الأولى واكتب لي: «لا أملك نطاقاً». سأشرح لك كيف تختار نطاقاً مناسباً أولاً. لا يمكن إرسال بريد موثوق باسم ترتيل من نطاق لا تملكه.

## الجزء الأول: تجهيز النطاق في Resend

### الخطوة 1: افتح Resend وسجل الدخول

1. افتح [resend.com](https://resend.com) من جهازك.
2. اضغط **Log in** أو **Sign in**.
3. اختر الدخول بواسطة GitHub إن كان حسابك في Resend مرتبطاً به؛ لا تحتاج إلى كتابة كلمة مرور إن كانت جلسة GitHub مفتوحة.
4. بعد الدخول، ابق في لوحة Resend ولا تغيّر أي إعدادات لا أذكرها هنا.

### الخطوة 2: أضف نطاق الإرسال

1. من القائمة الجانبية، اضغط **Domains**.
2. اضغط **Add Domain** أو **Add a domain**.
3. اكتب اسم نطاقك فقط، مثال: `example.com`.
   - لا تكتب `https://`.
   - لا تكتب `/` في النهاية.
   - لا تستخدم اسم موقع Manus المؤقت؛ استخدم نطاقاً تملكه أنت.
4. اختر المنطقة الافتراضية إن ظهر اختيار للمنطقة، ثم اضغط **Add**.

### الخطوة 3: انسخ سجلات DNS التي يعرضها Resend

بعد الإضافة، ستظهر لك قائمة سجلات باسم شبيه بالآتي: **Type** و**Name** و**Value**. قد تكون سجلات من نوع `TXT` أو `MX` أو `CNAME`، وتختلف أسماؤها وقيمها من حساب إلى آخر.

1. لا تغيّر أي حرف في القيم المعروضة.
2. خذ لقطة شاشة واضحة للقائمة، أو انسخ كل سجل في ملاحظة خاصة بك.
3. لا ترسل مفاتيح API إلينا؛ يمكنك إرسال صورة سجلات DNS فقط، فهي سجلات عامة مخصصة لإثبات ملكية النطاق.

## الجزء الثاني: إضافة سجلات DNS عند شركة النطاق

### الخطوة 4: افتح المكان الذي اشتريت منه النطاق

ادخل إلى حسابك عند الجهة التي تدير النطاق. قد تكون Cloudflare أو GoDaddy أو Namecheap أو غيرها. ابحث عن أحد هذه الخيارات: **DNS** أو **DNS Management** أو **Manage Zone** أو **إدارة سجلات DNS**.

### الخطوة 5: أضف السجلات واحداً واحداً

لكل سجل عرضه Resend:

1. اضغط **Add record** أو **إضافة سجل**.
2. اختر النوع المطابق تماماً: `TXT` أو `MX` أو `CNAME`.
3. انسخ خانة **Name** من Resend إلى خانة **Name / Host** هنا.
4. انسخ خانة **Value** من Resend إلى خانة **Content / Value / Target** هنا.
5. اترك **TTL** على `Auto` أو القيمة الافتراضية.
6. إذا كنت تستخدم Cloudflare، اجعل السجل `DNS only` عندما يكون من نوع CNAME خاص بالبريد، ولا تفعل Proxy له.
7. احفظ السجل، ثم كرر الخطوات لبقية السجلات.

> لا تحذف سجلات قديمة تخص موقعك أو بريدك. أضف سجلات Resend فقط. إذا ظهر لك تحذير من وجود سجل بالاسم نفسه، توقف وأرسل لي لقطة شاشة للتحذير قبل الاستبدال.

### الخطوة 6: تحقق من النطاق

1. ارجع إلى صفحة النطاق في Resend.
2. اضغط **Verify**.
3. إذا ظهر `Pending`، انتظر من 5 إلى 30 دقيقة ثم اضغط Verify مرة أخرى. في بعض شركات النطاق قد يستغرق التحديث أطول.
4. عندما تظهر الحالة **Verified** أو **Active**، اكتب لي: «تم توثيق نطاق Resend»، وأرسل اسم النطاق فقط.

## الجزء الثالث: منح ربط Resend الصلاحية المناسبة

الموصل الحالي يملك صلاحية إرسال فقط، وهي لا تكفي لإدارة النطاقات أو إعداد البريد. من صفحة **Integrations** في هذه المهمة أو في إعدادات الحساب، أعد ربط Resend ومنح الإذن لإدارة **Domains** و**Emails**. إن طلب منك Resend إنشاء مفتاح API:

1. سمِّه `Tarteel Supabase SMTP`.
2. امنحه صلاحية الإرسال وإدارة النطاقات وفق ما تعرضه Resend.
3. احتفظ بالمفتاح في مكان آمن؛ يظهر عادة مرة واحدة.
4. **لا تلصقه في المحادثة.** عندما تصل إلى هذه الخطوة، اكتب لي فقط: «المفتاح جاهز». سأفتح لك حقل أسرار آمن لإدخاله.

## الجزء الرابع: ما سأقوم به بعد ردك

بعد أن يصبح النطاق موثقاً وتصبح صلاحية Resend متاحة، سأفعل الآتي داخل الإعدادات الآمنة:

| المهمة | الإعداد |
|---|---|
| خادم البريد | `smtp.resend.com` |
| منفذ TLS | `465`، أو `587` عند اختيار STARTTLS |
| اسم مستخدم SMTP | `resend` |
| كلمة مرور SMTP | مفتاح Resend الذي تدخله في حقل الأسرار الآمن فقط |
| عنوان المرسل | `ترتيل <noreply@اسم-نطاقك>` |
| تأكيد البريد | مفعّل؛ لا يكتمل الدخول قبل تأكيد الرسالة |
| عنوان الموقع والتحويل | نطاق ترتيل المنشور، مع مسارات تأكيد البريد واستعادة كلمة المرور التي سأبنيها |

سأضيف لاحقاً صفحات التسجيل وتأكيد البريد واستعادة كلمة المرور داخل ترتيل، ثم نرسل رسالة اختبار إلى بريد تملكه أنت. لا يرسل التطبيق أي رسائل تجريبية إلى الطلاب أو أولياء الأمور.

## عند حدوث مشكلة

| المشكلة | التصرف الصحيح |
|---|---|
| لا أملك نطاقاً | أبلغني قبل شراء أو إعداد أي شيء. |
| Resend يقول Pending | انتظر ثم تحقق مجدداً؛ لا تضف سجلات مكررة. |
| يظهر سجل DNS موجود مسبقاً | لا تستبدله؛ أرسل لقطة شاشة. |
| لا يظهر زر إنشاء مفتاح | أعد ربط Resend بصلاحية إدارة النطاقات، ثم أخبرني. |
| لا أستطيع الكتابة في المتصفح | استخدم جهازاً فيه لوحة مفاتيح أو نسخ/لصق من هذا الدليل؛ لا ترسل كلمات المرور أو المفاتيح في الرسائل. |

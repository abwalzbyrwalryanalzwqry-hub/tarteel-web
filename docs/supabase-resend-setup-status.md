# حالة إعداد Supabase وResend لترتيل

## ما تم إنجازه

تم تفعيل ربط Supabase وResend ضمن الجلسة، وفحص منظمة Supabase المتصلة. أظهرت المنظمة مشروعين نشطين: `Manar Application` و`manar-production` في منطقة `ap-southeast-1`. أوقفت المشاريع السابقة بإذن المستخدم، ثم أنشئ مشروع مستقل ونشط باسم `tarteel-auth` في المنطقة نفسها. لم تدمج المنصة مع المشروع ولم تضاف أي مفاتيح إلى التطبيق.

## الإذن والحالة الحالية

أكد مالك المشروع كتابةً حذف المشروعين المذكورين بعد تنبيه واضح بأن الحذف نهائي. لا يوفر موصل Supabase المتاح عملية حذف مشروع، وفتح لوحة Supabase في المتصفح تطلب تسجيل دخول لم يكتمل بعد؛ لذلك بقيت المشاريع في حالة إيقاف فقط. لا تُحذف المشاريع إلا بعد استعادة جلسة لوحة Supabase المصرح بها أو توفير مسار إدارة يدعم الحذف.

## Resend

موصل Resend الحالي يملك صلاحية إرسال فقط، وفشل فحص النطاقات بسبب صلاحية API مقيدة. يلزم ربط حساب Resend بصلاحية إدارة النطاقات قبل إنشاء نطاق إرسال أو استخراج سجلات DNS وبيانات SMTP اللازمة لـ Supabase Auth.

## قرار التعليق

اختار مالك ترتيل الاستمرار في الوقت الحالي بالمصادقة المتاحة: **Manus OAuth وأكواد الوصول المقيدة**. لذلك يظل مشروع `tarteel-auth` منفصلاً وغير مستخدم من التطبيق، ولا يتم إعداد SMTP أو إرسال رسائل أو بناء تسجيل بالبريد حتى يتوفر نطاق مملوك وميزانية مناسبة. هذا التعليق لا يغير منظومة الصلاحيات وأكواد الدخول المنشورة في ترتيل.

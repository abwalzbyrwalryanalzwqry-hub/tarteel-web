# دليل قبول الصلاحيات متعددة الحسابات — ترتيل

## الهدف والحدود

يغطي هذا الدليل قبول الصلاحيات كما يراها المستخدم الحقيقي، إلى جانب اختبارات الخادم التي تحمي من تغيير المعرفات أو فتح مسار مباشر. لا ينشئ الدليل حسابات OAuth أو طلاباً أو سجلات حضور وهمية. تتطلب مرحلة القبول الحي حسابات حقيقية يملكها مدير المركز أو من يفوضه، وتستعمل بيانات قائمة للقراءة فقط ما لم يوافق المدير صراحة على تنفيذ عملية تعديل محددة.

## الحسابات المطلوبة

| الحساب الحقيقي | النطاق المطلوب | ما يثبت في القبول |
|---|---|---|
| مدير المركز | المركز | الإدارة الكاملة وسجل الأمان وإصدار الأكواد |
| مشرف | المركز | إدارة تعليمية دون إعدادات أو حذف المستخدمين |
| موجّه | حلقة أو حلقات محددة | قراءة الحلقات الممنوحة فقط |
| معلم | حلقة واحدة | إدارة طلاب وجلسات الحلقة الواحدة فقط |
| معلم مساعد | حلقة واحدة | الحضور والقراءة دون إدارة الطلاب |
| طالب | طالب واحد | التقدم والحفظ والمراجعة فقط |
| ولي أمر | ابن واحد | إنجاز وحضور وغياب وتقارير الابن فقط |

## طريقة الإعداد الآمنة

ينشئ المدير كود دخول منفصلاً لكل حساب من صفحة **المستخدمون والصلاحيات → أكواد الدخول**. يختار الدور والنطاق فقط ولا يضيف نطاق مركز إلى أكواد المعلم أو الطالب أو ولي الأمر. يجب ألا تستخدم هذه التجربة حساب المدير نفسه بعد تبديل دوره؛ المحاكاة مفيدة لمراجعة الواجهة فقط ولا تثبت صلاحيات الخادم.

## حالات القبول الحية

| الدور | تحقق النجاح | تحقق الرفض |
|---|---|---|
| المدير | عرض وإدارة إعدادات وأكواد مركزه | فتح مركز لا يملك عضويته يرفض |
| المشرف | عرض الطلاب والحلقات وتقارير المركز | تعديل الإعدادات أو حذف المستخدمين لا يظهر ويرفض مباشرة |
| الموجّه | قراءة الحلقة المخصصة وتقريرها | تبديل معرف حلقة في الرابط أو الطلب يرفض |
| المعلم | إضافة/تعديل طالب ضمن حلقته وتجهيز جلسة ضمنها | نقل طالب أو تغيير حلقة إلى أخرى يرفض |
| المساعد | تسجيل حضور ضمن حلقته | إنشاء طالب أو تعديل بياناته يرفض |
| الطالب | فتح ملفه ورؤية آخر الحفظ والمراجعة | فتح رابط طالب آخر أو قائمة الحضور يرفض |
| ولي الأمر | فتح ملف الابن وتقاريره وحضوره | فتح رابط ابن آخر أو إجراء تعديل يرفض |

## أدلة النجاح المطلوبة

يسجل المدير تاريخ الاختبار والحساب والدور والصفحة أو العملية والنتيجة. تحفظ لقطة شاشة للنجاح ولقطة لرسالة الرفض عند محاولة الوصول خارج النطاق، مع تجنب تصوير بيانات الطلاب الحساسة أو أكواد الدخول كاملة. أي نجاح خارج النطاق أو ظهور زر تعديل لدور قارئ يعد مانعاً للإطلاق ويعالج قبل متابعة النشر.

## التحقق البرمجي المنجز

يغطي `server/multiAccountAcceptance.test.ts` أدوار مدير المركز والمشرف والموجّه والمعلم والمساعد والطالب وولي الأمر، إضافة إلى الحساب غير النشط. يتحقق من الإذن ومن نطاق المركز والحلقة والطالب، ولا يكتب أي بيانات في قاعدة البيانات.

## نتيجة التحقق في الإصدار الحالي

أجري فحص TypeScript واختبارات Vitest الكاملة بعد إضافة مصفوفة القبول؛ نجحت 89 حالة في 29 ملف اختبار. كما عُرضت صفحة **المستخدمون والصلاحيات** على حساب مدير المركز وتأكد ظهور نقطة إصدار الأكواد وإدارة العضوية بصورة سليمة. كشف فحص البيانات المتاحة وجود حساب نشط واحد وعضوية مدير مركز نشطة واحدة فقط؛ لذلك لا يمكن ادعاء قبول تشغيلي متعدد الحسابات حتى يقدم مالك المركز حسابات OAuth حقيقية منفصلة للأدوار المطلوبة. لم ينشئ هذا التحقق أي مستخدم أو طالب أو سجل حضور أو جلسة اصطناعي.
